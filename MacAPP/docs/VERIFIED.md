# GS3104T-PRO 实测验证记录（macOS · 2.4G）

> 验证日期：2026-11-19 · 环境：macOS（arm64）+ 2.4G 接收器
> 设备：`GS3104T-PRO 2.4G`，`05AC:024F`，UsagePage `FF60` / Usage `61`

## 一、结论总览

| 项目 | 结果 |
|---|---|
| 配置通道识别 | ✅ **MI_03（32B Output/Input）** 是唯一命令通道 |
| MI_04（64B） | ❌ 仅回固定状态包 `0f 01 01 11`，**不是**命令通道 |
| 键盘休眠 | ✅ 确认为「零应答」的唯一原因；按任意键后立即恢复 |
| 读设备信息 `02` | ✅ 返回 `VID=05AC PID=024F` |
| 读电量 `20` | ✅ 返回 90%（与实际一致） |
| 写灯光 `05` | ✅ **背光实测变为纯红色**（用户目视确认） |
| 单键改键 `03` | ✅ 回显通过（Q→Q 等效默认，无破坏性） |
| 整层改键 `10`（21 块） | ⚠️ **21/21 回显通过，但物理未生效**（见下） |
| 单键改键 `03`（修正帧后） | ⚠️ 回显 `03 04 26` 正确，按 Q 仍输出 Q |
| APP 端到端自检 | ✅ `GANSS_CLI=1` → **ALL PASS** |

## 二、帧格式（32 字节，report id = 0）

```
发送（Output 报告 32B）
  [0]    cmd
  [1]    len      payload 长度
  [2]    sub      次级参数
  [3..]  payload
  [31]   checksum = sum(byte[0..30]) & 0xFF

应答（Input 报告 32B）
  [0..2] 回显 cmd / len / sub
  [3..]  设备数据
  [31]   checksum = sum(byte[0..30]) & 0xFF
```

成功判定：`resp[0..2] == req[0..2]` **且** `resp[31] == sum(resp[0..30])`。

## 三、已验证命令表

| cmd | len | 方向 | 语义 | 应答数据 |
|---|---|---|---|---|
| `0x02` | 16 | 读 | 设备信息 | `[7..8]=VID(AC 05)` `[9..10]=PID(4F 02)` |
| `0x20` | 1  | 读 | 电量 | `[3] = 电量%` |
| `0x05` | 16 | 写 | 灯光 | 空（头回显即成功） |
| `0x03` | 4  | 写 | 主层单键 | 空 |
| `0x0D` | 4  | 写 | Fn 层单键 | 空 |
| `0x10` | 28 | 写 | 主层键位块 0..20 | 空 |
| `0x12` | 28 | 写 | Fn 层键位块 0..20 | 空 |

**灯光 payload（`05`，16 字节）**：

```
[0] mode        [1] R  [2] G  [3] B
[8] colorful    [9] brightness  [10] speed  [11] direction
[14] 0xAA  [15] 0x55
```

**单键 payload（`03`/`0D`，4 字节）**：`[0]=key_index` `[1..4]=4字节记录`

**4 字节键位记录**：
- 默认 `00 00 00 00`
- 按键/组合 `02 mask usage 00`（mask = 修饰键位图，E0..E7 → bit0..7）
- 禁用 `01 00 00 00`
- 媒体 `03 usageLo usageHi 00`
- 宏 `06 slot 00 00`

## 四、休眠行为（重要）

- 2.4G 无线空闲后键盘休眠，**MI_03 完全零应答**（不是报文错误）
- MI_04 仍会回 `0f 01 01 11`（与命令内容无关，是状态包）——**不能**据此判断键盘在线
- 按任意键唤醒后，MI_03 立即恢复；官方驱动自身提示「无线设备请按一下按键解除休眠状态」
- APP 因此内置：探测失败 → 显示唤醒提示 → 每 1.5s 自动重探测 → 唤醒后自动读取状态

## 四点五、整层改键实测（未生效）

| 尝试 | 结果 |
|---|---|
| 整层 21 块下发 Q→B（无 AA55） | 21/21 回显 ✅，按 Q 仍输出 Q ❌ |
| 按 Fn+Tab 开启驱动自定义后重发 | 21/21 回显 ✅，按 Q 仍输出 Q ❌ |
| 补表尾 `AA 55` 终止符后重发 | 21/21 回显 ✅，按 Q 仍输出 Q ❌ |
| 单键 `03` 修正 key_index 到 sub 字段后重发 | 回显 `03 04 26` ✅，按 Q 仍输出 Q ❌ |
| 恢复默认（含 AA55） | 21/21 回显 ✅，键位已回到默认 |

**结论**：`0x10`/`0x12` 整层通道的**帧格式与回显校验全部正确**（设备逐块确认），
但设备未把数据写入生效区。可能原因：缺少会话前置命令（`04 18`）、
块序/长度边界、或该固件整层写入需配合 `04 02` 提交。
单键通路 `03`/`0D` 回显同样通过，物理效果未做破坏性验证。

**帧 bug 修正记录**：初版单键实现把 `key_index` 放在 payload[0]（错），上游
`keymap_single_plan` 是 `p[1:4]=(cmd, 4, key_index)` 即 **key_index 在 sub 字段**。
修正后回显 `03 04 26 02 00 05 00` 完全正确，但物理仍未生效 ——
说明根因不是帧布局，而是设备侧写入路径（可能需会话前置/提交命令）。

> 用户已确认：**按键映射功能暂缓**，不阻塞交付。已恢复默认键位，无残留。
